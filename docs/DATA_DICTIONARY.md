# Data dictionary

## File conventions

All tabular files are UTF-8 TSV with one header row, a period as decimal separator and `NA` for unavailable values. Numeric output is written with up to 12 significant digits. Boolean output is `true` or `false`; boolean input accepts `1`/`0` and the documented true/false equivalents. Empty values are treated as missing, not zero. Filenames and new field names use English identifiers; upstream EsViritu fields retain their exact spelling and case.

A sample identifier begins with a letter or digit and contains only letters, digits, periods, underscores or hyphens. It must match the upstream `sample_ID` and the prefix of `<sample_id>.detected_virus.info.tsv`. Metadata paths in `samples.tsv` are interpreted relative to that file's directory. Explicit command-line paths are interpreted relative to the current working directory.

## Input tables

### Sample manifest

The canonical schema is [samples_template.tsv](../templates/samples_template.tsv). The machine-readable field dictionary, including units and conditional requirements, is [input_fields.tsv](../templates/input_fields.tsv). Unknown column names and duplicate sample identifiers are rejected.

| Group | Fields | Requirement |
|---|---|---|
| Identity | `sample_id`, `sample_type` | Required. Types: `wastewater`, `negative_control`, `reference_material` |
| Input extract | `library_input_volume_ul`, `library_input_mass_ng`, `extract_nucleic_acid_concentration_ng_ul` | Required, positive; mixed DNA+RNA mass and concentration must agree with volume |
| ERCC addition | `ercc_mix`, `ercc_dilution_factor`, `ercc_spike_volume_ul`, `reaction_volume_ul` | Required; Mix1, positive dilution, nonnegative spike, positive reaction volume |
| Detection source | `info_tsv` | Required unless a command-line input location is supplied |
| Total input bases | `total_effective_bases`, or `fastp_json` with `fastp_section` | Required for the yield estimator; depth calibration can run without it |
| Alignment override | `alignment_metrics_tsv` | Optional reference-level metrics from `collect-bam` |
| Wastewater geometry | `extract_elution_volume_ul`, `extraction_input_volume_ul`, `concentrate_volume_ml`, `wastewater_volume_ml` | Required for wastewater conversion |
| Recovery | `pmmov_recovery_fraction`, or complete paired dPCR fields | Required for wastewater conversion |
| Validation | `alignment_qc_verified`, `detection_qc_verified`, `calibration_transfer_verified`, `loq_reaction_copies_ul` | Required by validated reporting; target-specific overrides are supported |
| Replicates | `batch_id`, `replicate_group` | Optional; define comparable technical replicates |
| Annotation | `notes` | Optional |

The dPCR alternative requires `pmmov_raw_extract_copies_ul`, `pmmov_post_extract_copies_ul`, `pmmov_raw_dilution`, `pmmov_post_dilution`, `raw_extract_elution_volume_ul`, `raw_extraction_input_volume_ul` and `pmmov_above_loq`, together with the wastewater geometry fields. Instrument values precede dilution correction. The supplied recovery fraction takes priority when present.

Input nucleic-acid mass and volumes are experimental measurements. The software never derives an actual extraction aliquot from post-lysis mixture volume, assumes a nominal elution equals a measured volume, or substitutes reaction volume for extract input.

### ERCC standards

`ercc_standards.tsv` generated by `init` is a copy of the bundled `ercc92_mix1.tsv`.

| Field | Definition |
|---|---|
| `ercc_id` | Official ERCC transcript identifier |
| `subgroup` | Manufacturer subgroup A, B, C or D |
| `stock_attomol_ul` | Nominal original Mix 1 concentration, amol/µL |
| `stock_copies_ul` | Derived stock concentration; calculations recompute it from attomoles and the Avogadro constant |
| `length_nt` | Length of the specific database reference sequence |
| `level` | Ascending ordinal of the nominal stock concentration; adjacent-level QC uses this ordering |
| `fit_include` | Standard-level eligibility flag; zero excludes the transcript from fitting but not from spiked mass |
| `concentration_source`, `length_source` | Public assignment and sequence provenance |

A custom `--ercc-standards` file must retain the 92 Mix 1 identifiers and coherent concentration ordering. Any independently assigned lot-specific concentrations must be documented by the investigator and are identified by the file checksum. The software does not establish their traceability.

### Target manifest

[targets_template.tsv](../templates/targets_template.tsv) defines the public schema. A full catalog may contain accessions not detected in the current run.

| Field | Definition |
|---|---|
| `accession` | Exact upstream `Accession` |
| `target_group` | Reference/assembly group to quantify once |
| `reference_length_nt` | Locked complete group length; for dsDNA the numerical length is in bp |
| `molecule_type` | Reviewed genome/material chemistry: ssRNA, dsRNA, ssDNA or dsDNA |
| `molecular_mass_per_nt_g_mol` | Average molar mass per reference position, required for yield conversion |
| `molecular_mass_source` | Evidence supporting the chemistry/factor assignment |
| `alignment_qc_verified` | Target-specific mapping/duplicate evidence declaration |
| `detection_qc_verified` | Target-specific detection/background evidence declaration |
| `calibration_transfer_verified` | Target-specific evidence that ERCC response transfers to the target |
| `loq_reaction_copies_ul` | Positive externally validated target LoQ on the starting-reaction scale |

Non-missing target validation fields override sample-level declarations; `NA` inherits the sample-level field. An explicit `0` overrides a sample-level true declaration. For segmented groups, all detected members must satisfy the validation declarations, and the largest supplied member LoQ is used. Complete group length and molecular-mass factor must be consistent across members.

`prepare-targets --db-dir` loads accession-resolved chemistry and mass from the checksum-validated catalog. Without a catalog, chemistry remains unavailable; rank names alone do not assign mass. Validation fields remain unavailable. Non-missing target fields override database defaults. A supplied molecular type must agree with its canonical factor; any explicit mass assignment requires `molecular_mass_source`. Assignment records a user declaration and does not establish calibration transfer.

### ERCC QC table

| Field | Definition |
|---|---|
| `sample_id` | Manifest sample identifier |
| `ercc_id` | Standard transcript identifier |
| `use_for_fit` | Zero excludes that sample/transcript combination |
| `reason` | Required nonempty reason for exclusion |

A true `use_for_fit` does not override a missing signal, failed read/breadth threshold or standard-level exclusion. Decisions should be prespecified or transparently justified, not selected to maximize R².

### Alignment metrics

`collect-bam` generates `accession`, `length_nt`, `aligned_bases`, `mean_depth`, `covered_bases` and `read_count`. `aligned_bases` is cumulative aligned read bases; `covered_bases` is the union of covered reference positions. A companion JSON records the BAM checksum, filtering rules and pysam version. The table supplies observations; external alignment validation remains a separate declaration.

## Main concentration outputs

`<sample_id>.reference_quantification.tsv` preserves every upstream row and field in source order. Two fields are inserted immediately after `RPKMF`: `concentration_reaction_copies_ul` and `concentration_wastewater`. Additional fields follow the complete source schema. No source value is replaced.

| Field | Unit / interpretation |
|---|---|
| `concentration_reaction_copies_ul` | Reporting-policy concentration in the total starting reaction, copies/µL; known assigned input for ERCC rows |
| `concentration_wastewater` | Reporting-policy wastewater concentration; unit in `wastewater_concentration_unit` |
| `concentration_extract_copies_ul` | Reporting-policy extract concentration, copies/µL |
| `estimated_reaction_copies_ul` | Model-derived reaction concentration before reporting-policy suppression |
| `estimated_extract_copies_ul` | Model-derived extract concentration before reporting-policy suppression |
| `estimated_wastewater_concentration` | Model-derived wastewater concentration if recovery conversion is available; same unit as the reported wastewater value |
| `reaction_concentration_unit` | `copies/uL` |
| `wastewater_concentration_unit` | `copies/mL` or `copies/L` |
| `quantification_method` | `sequencing_yield` or `depth_calibration` |
| `target_group` | Quantification group; ERCC identifier for standard rows |
| `reference_length_nt` | Locked reference length used in molecular/depth conversion |
| `quantification_aligned_bases` | Group-summed cumulative aligned bases |
| `molecular_mass_per_nt_g_mol` | Approximate average molar mass per reference position |
| `molecule_type` | Assigned ssRNA, dsRNA, ssDNA, dsDNA or unresolved category; describes the stated genome/material model |
| `molecular_annotation_status` | Catalog resolution, source disagreement, incomplete assembly or explicit target assignment |
| `quantification_molecular_mass_g_mol` | Theoretical mass of the complete quantification reference group, not necessarily the mass of one detected segment |
| `mass_model` | Declared average-position mass model or sourced custom assignment |
| `molecular_mass_source` | Source of the selected chemistry/mass assignment |
| `value_origin` | `assigned_standard` or `model_estimate` |
| `reporting_mode` | `validated` or `exploratory` |
| `target_validation_verified` | All supplied target evidence declarations and a positive LoQ are available; does not certify evidence quality |
| `reportable_target_concentration` | The target concentration satisfies the current reporting policy; false for standard rows |
| `within_calibration_range` | Target predictor/inferred input lies in the fitted ERCC range |
| `loq_reaction_copies_ul` | LoQ used for this target |
| `pmmov_recovery_fraction` | Supplied or dPCR-derived recovery fraction |
| `quantification_status` | Semicolon-delimited qualification codes |

`NA` means unavailable or suppressed, not zero and not proof of absence. Estimates can be present while reportable concentrations are `NA`. `target_validation_verified=true` can coexist with `below_loq`; validation availability and concentration acceptance are different conditions. Exploratory output must not be described as externally validated merely because a concentration is populated.

`<sample_id>.target_quantification.tsv` contains one row per target group and includes `sample_id`, detected accessions, complete length, detected reference length, aligned bases, mean depth, breadth and the concentration fields above. Alternative reference assemblies are distinct groups unless explicitly reviewed. Segment rows in the reference table repeat group concentration and must not be summed.

## Calibration and diagnostics

| File | Principal fields |
|---|---|
| `.calibration_points.tsv` | `ercc_id`, `length_nt`, `level`, stock/working concentrations, `added_copies`, `reaction_copies_ul`, `extract_equivalent_copies_ul`, `added_mass_ng`, observed signal, `detected`, `fit_used`, `fit_exclusion`, `included_in_model`, model log coordinates, fitted response and residual |
| `.calibration_model.tsv` | `slope`, `intercept`, `r2`, `rmse_log10`, `residual_degrees_of_freedom`, predictor range, equation, fit count, adjacent levels, mean/median yield, eligibility identifiers, acceptance and failure codes |
| `.reaction_concentration_model.tsv` | Algebraic reaction-scale equation; RNA factor 340. Its R² describes agreement with the transformed model, not an additional optimized fit |
| `.wastewater_conversion.tsv` | Actual volumes, PMMoV concentrations where derived, recovery source, recovery fraction, unit, extract-to-water multiplier and status |
| `replicate_diagnostics.tsv` | Batch/group/transcript, observation count, sample CV, assessment status and whether filtering was applied |
| `run_summary.tsv` | One sample/method per row, calibration status and coefficients, fitted count, estimated/reportable/externally validated target counts, out-of-range count, missing-mass count and conversion status |

The calibration point table always retains all 92 standards. A detected standard may be eligible for general QC but excluded from a particular model when its required signal is unavailable; `included_in_model` is the definitive model-membership field. `fit_exclusion` records general eligibility decisions.

Qualification codes include `calibration_failed`, `outside_calibration_range`, `below_loq`, `loq_unavailable`, `alignment_qc_unverified`, `detection_qc_unverified`, `calibration_transfer_unverified`, `partial_reference_detected`, `missing_molecular_mass_factor`, `inconsistent_database_assembly_length` and `wastewater_conversion_unavailable`. `accepted` indicates no additional qualification flags. `known_ercc_input` marks an assigned standard rather than an inferred target concentration.

## Provenance

`inputs/` stores the selected sample records, resolved target metadata, standard table and one calculated ERCC-input table per sample. When a catalog is used, `molecular_annotations.tsv` contains the exact annotation rows for all detected references, including ERCC. Run and sample manifests include the complete catalog and manifest hashes, database metadata hash, model and classification policy. `run_manifest.json` records software version, UTC timestamps, invocation, Python/platform/dependency versions, input checksums, thresholds, reporting mode and selected samples. Each `.analysis_manifest.json` adds source detection and alignment-metrics checksums, fastp checksum when used, total-base source, total input mass, calibration details and recovery conversion.

The manifests record actual input locations for traceability. They contain caller-supplied paths only; the distributed workflow has no fixed experiment directory. Shared analyses may require redaction of local path metadata in accordance with the study's data-management policy, without changing computational values or input checksums.

## Molecular annotation database

The full field dictionary and generation policy are documented in [MOLECULAR_ANNOTATIONS](MOLECULAR_ANNOTATIONS.md). The file `virus_pathogen_database.molecular_annotations.tsv` is a separate database sidecar; its `accession` key matches the unchanged metadata `Accession` column exactly. Runtime target-level molecular mass uses a coherent complete assembly rather than a detected-segment length.
